# 创作与版本规范

## 文档头与状态

每份工作文档填写：项目代号、文档名称、负责人、版本、更新日期、状态、关联上游版本。状态依次为：草稿 → 待审核 → 待修改 / 已确认 → 已交付 → 已归档。“已确认”由指定审核人写入姓名、日期和结论；内容变更后重新送审。

版本建议：v0.1 初稿，v0.2 修订，v1.0 首次确认交付；交付后勘误升补丁位，剧情或镜头调整升次版本，结构性重写升主版本。所有变更记录影响范围。

## 编号与文件名

- 项目代号：英文大写，如 DEMO；集号 EP001；场号 SC01（集内唯一）；镜号 SH001（场内唯一）。
- 完整镜头编号：DEMO-EP001-SC01-SH001。镜头删除保留作废记录，新增镜头用未使用编号，避免素材错链。
- 单集文件：EP001_剧本.md；分镜：EP001_分镜.md。人物、场景、道具分别用 CHAR001、LOC001、PROP001。
- 日期使用 YYYY-MM-DD。版本、集号、场号在所有交接材料中一致。

## 创作原则

用可拍摄的动作表达信息；人物行为必须有动机和代价。每集写明人物目标、阻碍、变化、结尾悬念及其后续兑现位置。节奏服务故事，避免仅用重复羞辱、误会拖延情节。

精品剧进一步追踪主题、人物弧光、伏笔回收和视听表达；AIGC 镜头需说明主体、动作、空间、时长与连续性，避免单镜头堆叠无法执行的复杂动作。

## 公开提交与协作

提交前检查正文、附件及素材链接的公开权限；未公开原稿、个人联系方式、合同、密钥、未授权肖像及第三方素材不进入本库。忽略规则仅为辅助，不能替代人工检查。

建议分支：project/项目代号-修改主题。PR 说明修改目的、涉及文件、影响集数、审核人及自检结果；主分支以确认记录为准。正式交付记录提交 SHA；后续修订另写变更记录，不覆盖原验收事实。
